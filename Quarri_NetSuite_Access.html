IT setup guide

NetSuite access for Quarri

What we need from your team so Quarri can read your NetSuite data automatically: sales, purchasing, inventory and the reference lists behind them. Read-only, and about twenty minutes of work for someone with NetSuite Administrator rights.

Background
How access works

Quarri connects to NetSuite through the REST API using token-based authentication. You create an integration record, a role and an access token in your own account, and send us the resulting key and secret pairs. No user login is involved, and nothing breaks when someone changes their password.

Read-only throughout

Every permission in the role is View level. Quarri cannot create, change or delete anything in NetSuite.

Only what you grant

The role lists exactly the records Quarri can see. Anything you leave off the role stays invisible to the connection.

Fully under your control

The integration record, role and token all live in your account. Revoke the token or disable the integration at any time and Quarri's access stops.

Read this first: two settings cause most of the trouble.

1. On the integration record in step 2, NetSuite offers OAuth 2.0 options that must be left unticked. Ticked, they can stop the record saving.

2. The access token in step 4 must be created under the custom role from step 3, not a standard NetSuite role. A token on a standard role is rejected with "Invalid login attempt".

Before you start
What you will need
  • NetSuite Administrator access, or a role that can enable features and create integration records, roles and access tokens.
  • A user to hold the token. It can be your own. The token belongs to that user, so choose someone who will stay: if the user is deactivated, the connection stops.
  • About twenty minutes. The secrets are shown only once, so have somewhere safe to paste them as you go.
Setup
Setup steps

Six steps, all in the NetSuite user interface. Steps 2 and 4 each show you a pair of secrets once only.

1

Turn on the two features

Go to Setup → Company → Enable Features → SuiteCloud.

  • Tick REST Web Services.
  • Tick Token-Based Authentication.

Leave OAuth 2.0 alone. Quarri does not use it. Click Save.

2

Create the integration record

Go to Setup → Integration → Manage Integrations → New. Name it Quarri and set State to Enabled. Then open the Authentication tab and set it exactly as follows.

SettingValue
Token-Based AuthenticationTicked
Authorization Code GrantUnticked
Client CredentialsUnticked
Redirect URILeave blank

This is the step that trips people up. On a new integration record NetSuite ticks the OAuth 2.0 options by default. Left ticked, they can stop this step saving, and the setup cannot go any further. Untick them, leave the Redirect URI empty, and keep Token-Based Authentication as the only method.

Click Save. NetSuite now shows the Consumer Key and Consumer Secret once only. Copy both before you leave the page. If you miss them, reset the credentials on the integration record and copy the new pair.

3

Create a custom role and give it to your user

Go to Setup → Users/Roles → Manage Roles → New. Name it Quarri Integration, or any clear name. Set the permissions below, all at View level except the two Setup permissions. Permission names vary slightly between NetSuite versions.

WherePermissions
SetupLog in using Access Tokens and REST Web Services. Without both, the token cannot connect.
SalesSales orders, invoices, item fulfilments, customers
PurchasingPurchase orders, vendor bills, item receipts, vendors
InventoryItems, inventory, inventory adjustments
Reference listsCurrencies, subsidiaries, locations, departments, classes. Without these, reports show codes instead of names.

Then, at the top of the role page, find Subsidiary Restrictions and set Accessible Subsidiaries to All. The default is User Subsidiary, which limits Quarri to the one subsidiary your user belongs to. If you run more than one subsidiary, we would otherwise miss the rest.

Save the role, then assign it to your user: open the user's employee record, go to Access → Roles, add Quarri Integration and save.

Do not skip this step by reusing a standard role. Standard roles such as NetSuite Support Centre cannot log in through REST web services. A token created under one is rejected with "Invalid login attempt", even though every other step was done correctly.

4

Create the access token

Go to Setup → Users/Roles → Access Tokens → New Access Token and choose:

  • Application: the Quarri integration record from step 2.
  • User: the user you gave the role to in step 3.
  • Role: Quarri Integration. Check this one before you save, because the dropdown may offer a different role first.

Click Save. NetSuite shows the Token ID and Token Secret once only. Copy both now.

5

Find your Account ID

Go to Setup → Company → Company Information and copy the Account ID. A production account is a number. A sandbox account has a suffix such as _SB1, so please copy it exactly as shown and tell us which one it is.

6

Send us the five values

Please share the two secrets through a secure channel, such as a password manager share or an encrypted message, rather than plain email. We store them encrypted on our side. Screenshots of the secrets count as plain email, so please paste the text instead.

If something goes wrong
Troubleshooting

Every problem we have seen so far is one of these. None of them needs the whole setup repeated.

What you seeWhyFix
An error when saving the integration record The OAuth 2.0 options are ticked by default. On the Authentication tab, tick only Token-Based Authentication. Untick Authorization Code Grant and Client Credentials, and leave Redirect URI blank. Save and copy the Consumer Key and Secret.
Quarri reports "Invalid login attempt" The token was created under a standard role, or the role is missing Log in using Access Tokens or REST Web Services. Complete step 3, then create a new access token under that role (step 4). Send us the new Token ID and Secret. The Consumer Key and Secret do not change.
Reports show codes instead of currency, location or department names The role cannot view the reference lists. Add View on Currencies, Subsidiaries, Locations, Departments and Classes to the role. No new token is needed, because role changes apply to the existing token.
Data from only one subsidiary Accessible Subsidiaries is still on User Subsidiary. Set it to All on the role page. No new token is needed.
To see exactly why a login was refused, go to Setup → Users/Roles → User Management → View Login Audit Trail. Failed attempts from Quarri are listed with the rejection reason in the detail column. Send us a screenshot of that row if you would like us to look.
FAQ
Common questions
Is this read-only?

Yes. The two Setup permissions only allow the token to connect. Every record permission is View level, so Quarri cannot create, edit or delete anything in NetSuite.

How do I revoke access?

Revoke the token under Setup → Users/Roles → Access Tokens, or set the integration record's state to disabled. Quarri's access stops as soon as you do either.

Does the connection use a person's login?

No. It uses the key and secret pairs, with no password. The token is attached to the user you chose in step 4, so access ends if that user is deactivated.

Any questions, ask
