IT setup guide

SharePoint access for Quarri

What we need from your team so Quarri can pick up files automatically from an agreed SharePoint document library, and file them into processed and archive folders once they are loaded. About fifteen minutes of work for someone with Entra ID and SharePoint admin rights.

Background
How access works

Quarri connects to SharePoint through the Microsoft Graph API, using an app registration in your own Microsoft Entra ID tenant with the Sites.Selected application permission. This is Microsoft's current least-privilege model for exactly this scenario.

It has three properties your security team will care about.

Zero access by default

Even after admin consent, the app can reach no sites at all until you explicitly grant it access to a named site. It cannot browse, enumerate or discover anything else in your tenant.

Scoped to the sites you choose

You grant access site by site, at a role you choose. We need Write on the one exchange site. Everything else in your SharePoint stays invisible to the app.

Fully under your control

The app lives in your tenant. You can audit the grant, revoke it, or expire the credential at any time, cutting off access instantly.

Why not the older SharePoint App-Only method? That model, Azure ACS and SharePoint Add-ins, was permanently retired by Microsoft on 2 April 2026 and no longer works for any tenant. The Entra ID and Graph approach below is Microsoft's supported replacement.
Setup
Setup steps

Six steps. Steps 2 to 5 are done in the Entra admin center and SharePoint; step 1 is a decision and step 6 is a reply to us.

1

Create or choose the SharePoint site to share with Quarri

A dedicated site keeps the boundary clean. The grant in step 5 covers a whole site, so a purpose-made site means Quarri can never see anything unrelated.

We suggest a site such as https://<yourtenant>.sharepoint.com/sites/quarri-exchange, with a document library containing folders like inbox/, processed/ and failed/. An existing site works too, if you are comfortable granting write access to all of it.

2

Register an application in Microsoft Entra ID

This is the identity Quarri authenticates as. It is single-tenant: it exists only in your directory.

In the Entra admin center, go to Identity → Applications → App registrations → New registration.

  • Name: Quarri Data Connector. Any clear name works.
  • Supported account types: accounts in this organisational directory only.
  • Redirect URI: leave blank. It is not needed for server-to-server access.
3

Add the Sites.Selected permission and grant admin consent

This is the only Graph permission the app needs. It deliberately grants nothing on its own. Step 5 is what actually opens a site.

On the app registration, go to API permissions → Add a permission → Microsoft Graph → Application permissions → Sites.Selected → Add, then click Grant admin consent.

Please do not add broader permissions such as Sites.Read.All or Sites.ReadWrite.All. We do not want them, and Sites.Selected is sufficient.

4

Create a credential for the app

This is what Quarri's servers use to sign in as the app.

Preferred: a client secret. Simplest to manage on both sides. On the app registration, go to Certificates & secrets → New client secret. Choose an expiry of twelve to twenty-four months and note the date, because we will both want a reminder to rotate it. Copy the secret Value immediately, as it is only shown once.

Alternative: a certificate. If your policy prefers certificate credentials, we are happy to generate a key pair and send you the public certificate to upload instead. Tell us and we will include it with our reply.

5

Grant the app access to the site

This is the step that actually opens the door, and only to this one site. Write lets us download files and move them between folders. It does not allow site administration or permission changes.

Using PnP PowerShell, run by a SharePoint administrator:

Connect-PnPOnline "https://<yourtenant>.sharepoint.com/sites/quarri-exchange" -Interactive Grant-PnPAzureADAppSitePermission ` -AppId "<Application (client) ID from step 2>" ` -DisplayName "Quarri Data Connector" ` -Site "https://<yourtenant>.sharepoint.com/sites/quarri-exchange" ` -Permissions Write

You can verify or revoke the grant at any time with Get-PnPAzureADAppSitePermission and Revoke-PnPAzureADAppSitePermission. The same grant can also be made with a Graph API call to POST /sites/{site-id}/permissions if you prefer, and we are glad to provide that variant.

6

Send us the connection details

Everything except the secret is non-sensitive. Please share the secret value through a secure channel, such as a password manager share or an encrypted message, rather than plain email. We store it encrypted on our side.

Advanced
Optional hardening

None of this is required. It is here because security teams usually ask, and it is easier to answer up front.

IP restriction

Quarri's servers use a small set of static egress IP addresses, and we will supply the list. If you license Entra Workload ID Premium, a Conditional Access policy for workload identities can restrict this app's sign-ins to those addresses.

Tighter than site scoping

Microsoft also supports newer per-list and per-folder grants, Files.SelectedOperations.Selected and related permissions. We suggest the dedicated-site approach above instead, because it achieves the same isolation with much simpler administration. If your policy requires the granular model, we can work with it.

Audit

The app's activity appears in the Microsoft 365 unified audit log like any other Graph application, under the app's client ID.

Any questions, ask

We are glad to walk through any step on a call, or to do the PowerShell together while you hold the admin session.
